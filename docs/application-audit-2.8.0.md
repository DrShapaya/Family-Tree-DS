# Аудит приложения AndroidFT 2.8.0

Дата проверки: 10.09.2026.

Проверены основной экран и жизненный цикл Activity, импорт и экспорт файлов, хранение дерева и медиа, восстановление версий, GitHub-синхронизация и приглашения, виджеты, AndroidManifest, резервное копирование, отрисовка дерева и мастерская оформления.

## Исправлено в ходе аудита

- Исправлен старый photo picker: на Android до API 33 URI каталога изображений теперь передаётся вместе с MIME через `setDataAndType`, поэтому выбор фотографии не теряет источник.
- Входящий `.ftree` URI очищается из повторно используемого Intent после принятия. Повторный импорт после пересоздания Activity больше не выполняется.
- Освобождается незавершённый PNG/tiles export при отмене системного выбора файла или результате без URI.
- Награда за рекламу защищена от повторного callback SDK; тестовая выдача токенов доступна только в debug-сборке.
- Очередь виджетов теперь проверяет ревизию каждого экземпляра. Старое массовое обновление не может перезаписать более свежий размер или настройки одного виджета.
- Убрано принудительное разделение языковых ресурсов в App Bundle, чтобы ручная смена языка и виджеты не теряли строки.
- Отступы верхней панели берутся из WindowInsets, без внутреннего системного ресурса `status_bar_height`.
- В растительных краях и связях добавлен кэш прозрачных bitmap-слоёв. Геометрия и полная детализация листьев сохраняются; для приближения используются варианты 1×, 2× и 3×. Слишком большой слой ограничен по площади, а общий кэш — 32 МБ; при превышении используется безопасная векторная отрисовка.
- Убрана причина повторных пересборок на больших деревьях: кэш растительных карточек больше не очищается после первых 20 элементов, ключи не создают строки на каждом кадре, а длинные связи при приближении рисуются из сохранённого `Picture`. Это сохраняет все прожилки и лепестки без тяжёлой генерации bitmap во время pinch-gesture.
- У внешнего обработчика `.ftree` оставлено только read-only URI-разрешение; права записи, persistable и prefix больше не передаются.
- Растительное полотно теперь использует очищенную центральную область исходной иллюстрации без рамок, записок и компаса. Поле закреплено в мировых координатах, повтор не зеркалится и вынесен на большие интервалы, поэтому мотивы не мелькают при отдалении.
- Растительные рамки виджетов рисуются по внешнему контуру с адаптацией к светлому и тёмному фону; листья больше не прячутся во внутреннем отступе. Огненные карточки стали светлее, а искры и внутренние угольки живут в медленном детерминированном цикле.

## Риски, которые остаются

### Высокий архитектурный риск: OAuth GitHub

Мобильный APK содержит client secret, а OAuth-запросы используют широкие scopes `repo gist`. Секрет в native-приложении нельзя считать конфиденциальным: APK можно распаковать. Сейчас риск снижен PKCE, проверкой state в constant-time и шифрованием токена Android Keystore, но окончательное решение — GitHub App/fine-grained permissions или серверный обмен токена.

PKCE уже включён для браузерного входа: приложение создаёт одноразовый `code_verifier`, отправляет в GitHub только его SHA-256 `code_challenge`, а затем меняет код на токен только с исходным verifier. Перехваченный redirect без verifier не позволяет завершить вход. Это не уменьшает права уже выданного токена.

Более узкая модель разрешений потребует заменить классический OAuth `repo gist` на GitHub App или fine-grained access. Для текущей синхронизации отдельно нужны операции с содержимым приватного репозитория, releases/assets, collaborators/invitations и Gist-комментариями. После миграции пользователь будет выдавать доступ только выбранному репозиторию и конкретным операциям; чтение чужих репозиториев и полный доступ ко всем приватным репозиториям исчезнут. Цена — серверный обмен токена или более сложная установка GitHub App, а часть старых сценариев приглашений придётся переписать.

### Средний риск: невалидный `.ftree` может оставить orphan media

Медиа импортируется в content-addressed store до того, как полностью проверены `tree.json` и все ссылки. Повреждённый пакет не портит текущее дерево, но может оставить неиспользуемые файлы. Следующий безопасный шаг — staged media с commit после успешной валидации либо сборщик orphan media.

### Средний риск: лимит контейнера

Импорт защищён лимитами ZIP, дерева, количества записей и суммарного медиа, но верхняя граница контейнера — 1 ГБ. Это контролирует архивную атаку, но на недорогих устройствах всё ещё может занять значительную часть диска. Нужен продуктовый лимит или явное подтверждение больших импортов.

### Низкий риск: lint и UI-долги

Оставшиеся предупреждения относятся к переносам строк, жёстко заданным RTL-отступам, подсказкам для accessibility и отдельным allocations в вспомогательных экранах. Их стоит исправлять отдельным UI-проходом, чтобы не смешивать с проверенными изменениями хранения и экспорта.

## Вывод

В текущей версии критических воспроизводимых crash и потери текущего дерева в проверенных сценариях не обнаружено. Главный оставшийся риск — модель GitHub OAuth и широкие разрешения; главный технический долг импорта — уборка orphan media после невалидного пакета.
