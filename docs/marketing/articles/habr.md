# Habr: Как я сделал офлайн-first семейное дерево на Android: Canvas, .ftree, GEDCOM и синхронизация через GitHub

**Лид:** Разбираю архитектуру Family Tree DS - нативного Android-приложения для семейного дерева, локального архива, экспортов и приватной синхронизации без собственного сервера.

![Family Tree DS: семейное дерево](screenshots/01-tree.png)

Я делаю **Family Tree DS** - Android-приложение для создания семейного дерева и хранения семейного архива. На первый взгляд задача выглядит как обычный редактор карточек и связей, но внутри быстро появляются интересные инженерные вопросы:

- как рисовать большое дерево без WebView;
- как хранить фото, документы и истории вместе с деревом;
- как переносить архив между устройствами;
- как сохранить совместимость с генеалогическими программами;
- как дать семье синхронизацию без собственного бэкенда;
- как не превратить чувствительные семейные данные в обязательный облачный сервис.

Ниже - технический разбор решений, которые сейчас используются в приложении.

## Почему нативный Canvas, а не WebView

Первая версия проекта была ближе к веб-подходу. В нативной версии я ушёл в Android Canvas.

Причины:

- стабильнее поведение жестов и масштабирования;
- меньше прослойка между данными и отрисовкой;
- проще контролировать выделение карточек, направляющие, лассо, фокус ветвей;
- лучше ощущается как Android-приложение, а не встроенная страница.

Дерево - это рабочее поле. Пользователь двигает полотно, масштабирует, выбирает карточки, строит связи, запускает авторасстановку. Для такого интерфейса Canvas оказался более предсказуемым.

## Модель данных

В основе дерева есть люди, связи, направляющие, настройки отображения, архивы, фотоальбомы и вложения.

Карточка человека хранит:

- имя;
- пол;
- даты рождения и ухода;
- место;
- фото;
- заметки;
- воспоминания и вложения.

![Карточка человека](screenshots/02-person-card.png)

Связи бывают родительские, партнёрские, родственные и братские. Это важно, потому что реальная родословная редко выглядит как аккуратное бинарное дерево.

## Авторасстановка дерева

Отдельная часть проекта - раскладка семейных ветвей. Приложение должно уметь:

- держать поколения на понятных уровнях;
- не ломать уже расставленные пользователем ветки без необходимости;
- работать с несколькими партнёрами;
- учитывать детей разных союзов;
- давать повторяемый результат;
- позволять локальное упорядочивание выбранной ветки или потомков.

В новых версиях авторасстановка получила локальное обучение весов: после ручной коррекции приложение постепенно подстраивает решатель под стиль пользователя. Логи для тестирования можно скопировать без ФИО, фото и заметок.

## .ftree как переносимый контейнер

Обычный JSON быстро перестаёт быть удобным, когда появляются фотографии и документы. Поэтому для переноса используется `.ftree`.

Это переносимый контейнер дерева: внутри структура, метаданные и медиа. Пользователь может отправить один файл родственнику, сохранить резервную копию или перенести дерево на другой телефон.

Параллельно поддерживаются:

- JSON - для простого обмена и диагностики;
- GEDCOM - для совместимости с генеалогическими программами;
- PDF - для постраничной печати;
- PNG - для быстрого просмотра;
- тайловый PNG - для больших деревьев.

## GEDCOM

GEDCOM нужен не потому, что это самый удобный формат, а потому что это язык обмена между генеалогическими программами. Если пользователь уже вёл дерево где-то ещё, он не должен начинать с нуля.

Family Tree DS поддерживает импорт и экспорт GEDCOM, чтобы приложение не становилось закрытой коробкой.

## Каталог людей и поиск обычным языком

Когда дерево растёт, визуального полотна уже мало. Нужен список людей.

![Раздел Люди](screenshots/03-people-list.png)

В разделе «Люди» есть поиск по ФИО, году, месту, фильтры, сортировка, фотоальбомы и умные запросы обычным языком: без фото, без даты рождения, ближайшие дни рождения, предки, потомки, родственники человека.

Это не внешний AI-сервис. Логика работает локально по данным дерева.

## Синхронизация без своего сервера

Я не хотел делать обязательный аккаунт и отдельный бэкенд для семейных данных. Поэтому онлайн-режим в приложении необязательный.

Если пользователь включает его, дерево хранится в приватном GitHub-репозитории. Медиа передаются через служебные release assets, участники подключаются по приглашениям, а глава может выдать просмотр или редактирование.

Такой подход не идеален для массового потребительского сервиса, но он хорошо подходит для проекта, где важны прозрачность, переносимость и отсутствие обязательного центрального сервера.

## Виджеты дней рождения

Отдельный практичный слой - Android-виджеты. Они показывают ближайшие дни рождения родственников и делают дерево полезным не только во время редактирования.

![Виджеты дней рождения](screenshots/04-birthday-widgets.png)

## Что получилось

Сейчас Family Tree DS умеет:

- создавать семейное дерево;
- хранить карточки людей с фото и заметками;
- вести семейные истории и документы;
- создавать фотоальбомы;
- импортировать и экспортировать GEDCOM;
- переносить дерево одним `.ftree` файлом;
- экспортировать PDF/PNG;
- показывать виджеты дней рождения;
- синхронизировать приватное дерево через GitHub.
