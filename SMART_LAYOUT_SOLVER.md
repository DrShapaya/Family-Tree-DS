# Умный решатель компоновки семейного дерева

Статус: этапы A–B завершены; безопасный локальный контур этапа C подключён к автоматической компоновке; пошаговое полное перестроение, финальное уплотнение и идемпотентность этапа D подключены 10 августа 2026 года.

Этот файл — основной план перехода от текущих эвристик `TreeLayoutEngine` к единому решателю. Новые случаи компоновки сначала должны описываться здесь как ограничение, операция или критерий качества, а не добавляться в код как отдельная проверка конкретной формы дерева.

## 1. Цель

Решатель должен получать граф родственных связей и выбирать лучший из нескольких безопасных вариантов размещения.

Он должен поддерживать два режима:

1. Локальное обновление после добавления человека: перестраивается минимальная затронутая область, остальное дерево остаётся неподвижным.
2. Полное упорядочивание: дерево быстро строится заново по тем же операциям, начиная с основной карточки в центре поля.

Результат не должен зависеть от ФИО. Старые координаты используются только в локальном режиме как якоря стабильности. При полном упорядочивании порядок равнозначных людей определяется связями, порядком создания и, если доступны, датами рождения.

## 2. Что есть сейчас

- Граф связей: родители, партнёры, дети, братья и сёстры.
- Локальная компоновка после добавления человека.
- Пошаговое полное перестроение через те же локальные операции.
- Семейные и простые отступы.
- Сохранение основного ствола при локальных изменениях.
- Сравнение контуров одинаковых ветвей и зеркальное распределение места.
- Регрессионные тесты по проблемам 1–11 и синтетическим большим деревьям.

Текущий код уже структурный, но в спорной ситуации обычно выбирает один вариант. Решатель должен уметь создать несколько вариантов и сравнить их общей функцией качества.

## 3. Модель решателя

### 3.1. Семейный граф

Перед размещением обычные связи преобразуются в смысловые узлы:

- `PersonNode` — карточка человека;
- `PartnerUnit` — один человек или группа партнёров одного поколения;
- `ParentFamily` — конкретный набор родителей и их общие дети;
- `SiblingGroup` — дети одной родительской семьи;
- `Branch` — связная боковая ветвь;
- `Component` — отдельное несвязанное дерево.

Для каждого блока рассчитываются:

- поколение;
- корневая карточка;
- люди на каждом уровне;
- левый и правый контуры по уровням;
- ширина и высота;
- наличие основной карточки;
- степень допустимого перемещения;
- структурная сигнатура для поиска симметрии.

### 3.2. Жёсткие ограничения

Решение отклоняется полностью, если нарушено хотя бы одно условие:

- карточки пересекаются;
- партнёры находятся на разных уровнях без явного ручного исключения;
- родитель расположен не выше ребёнка;
- родные братья и сёстры находятся на разных уровнях;
- карточка выходит за допустимые границы рабочего поля;
- пропадает или меняется родственная связь;
- нарушается минимальный отступ между карточками;
- между независимыми семейными ветвями нет семейного отступа;
- одна карточка получает две разные позиции;
- результат содержит `NaN`, бесконечные или не привязанные к сетке координаты.

### 3.3. Мягкие ограничения и функция оценки

Каждый допустимый вариант получает числовой штраф. Чем меньше штраф, тем лучше решение.

Начальная формула:

```text
score =
    lineCrossings                 * W_CROSSINGS
  + movedExistingDistance        * W_MOVEMENT
  + movedMainTrunkDistance       * W_MAIN_TRUNK
  + totalTreeWidth               * W_WIDTH
  + totalTreeHeight              * W_HEIGHT
  + familyCenterError            * W_CENTER
  + symmetryError                * W_SYMMETRY
  + wrongAncestrySideDistance    * W_SIDE
  + unnecessaryEmptyCells        * W_EMPTY
  + changedSiblingOrder          * W_ORDER
  + bentConnectionLength         * W_LINES
```

Приоритеты:

1. Никаких наложений и неправильных поколений.
2. Не двигать основную ветвь без необходимости.
3. Не двигать далёкие незатронутые семьи.
4. Сохранять правильные стороны отцовской и материнской ветвей.
5. Центрировать родителей и детей.
6. Сохранять или создавать симметрию.
7. Минимизировать ширину дерева и пустое пространство.
8. Минимизировать пересечения и длину линий.

Все веса должны находиться в одном объекте `LayoutWeights`, а не быть разбросаны по условиям в коде.

## 4. Генерация вариантов

Для каждой затронутой области решатель создаёт ограниченное число кандидатов:

- сдвинуть только новую карточку;
- сдвинуть её семейный блок;
- сдвинуть боковую ветвь;
- раздвинуть две соседние ветви поровну;
- сдвинуть несколько ветвей пропорционально свободному месту;
- поменять местами простого родственника и широкую семейную ветвь;
- переставить равнозначных братьев или сестёр;
- зеркально расположить структурно одинаковые ветви;
- уплотнить внутренние отступы, не меняя семейные границы;
- расширить рабочее поле, если перемещение хуже расширения.

Для каждой операции должны быть явно указаны:

- затронутые карточки;
- неподвижные якоря;
- допустимые направления;
- диапазон сдвига по сетке;
- причина создания кандидата;
- обратимость операции.

## 5. Поиск лучшего решения

Первый вариант реализации — детерминированный beam search без нейросети:

1. Построить исходное состояние затронутой области.
2. Создать кандидаты первого шага.
3. Отбросить нарушающие жёсткие ограничения.
4. Оценить оставшиеся состояния.
5. Оставить лучшие `K` вариантов.
6. Для них создать следующий уровень операций.
7. Остановиться после ограничения по глубине или отсутствия улучшений.
8. Применить лучший вариант одной командой Undo/Redo.

Начальные ограничения производительности:

- локальное добавление: до 16 кандидатов на уровень, глубина до 4;
- полное перестроение: до 32 кандидатов на спорный семейный узел;
- обязательная детерминированность результата;
- локальное действие на дереве из 500 карточек — желательно менее 100 мс;
- полное упорядочивание 500 карточек — желательно менее 1 секунды на среднем Android-устройстве.

## 6. Локальный режим

После добавления человека определяется минимальная область влияния:

```text
новые карточки
  -> их партнёрская семья
  -> группа братьев и сестёр
  -> общие родители
  -> соседние ветви с пересекающимися контурами
  -> предки, которых нужно повторно центрировать
```

Карточки за пределами области получают бесконечный или очень большой штраф за перемещение. Область расширяется только тогда, когда внутри неё нет допустимого решения.

Локальный режим обязан сохранять:

- координаты основной карточки;
- положение камеры;
- поколения существующих карточек;
- ручные отступы, если они не создают конфликт;
- далёкие ветви, не участвующие в конфликте.

## 7. Полное упорядочивание

Полное упорядочивание использует тот же решатель, но без штрафа за изменение старых координат:

1. Основная карточка ставится в центр поля.
2. Добавляются партнёры.
3. Добавляются родители основной пары.
4. Добавляются братья и сёстры.
5. Добавляются партнёры и дети боковых родственников.
6. Выполняется переход к следующему поколению.
7. После каждого семейного шага решатель выбирает лучший локальный вариант.
8. В конце выполняется глобальная проверка ограничений и лёгкое уплотнение без изменения структуры.

Несвязанные компоненты строятся отдельно, затем размещаются с семейным отступом.

## 8. Особые структуры

Для следующих случаев нужны отдельные модели данных, но не отдельные координатные шаблоны:

- несколько партнёров и дети от разных браков;
- разведённые пары с увеличенным пользовательским расстоянием;
- сводные братья и сёстры;
- один известный родитель;
- более двух родителей;
- явная связь братьев без известных родителей;
- двоюродные браки и циклы в родословной;
- одна карточка, входящая в две ветви;
- приёмные и биологические связи;
- закреплённые карточки;
- несвязанные деревья;
- противоречивые или неполные связи.

Циклический граф нельзя раскладывать как обычное дерево. Для него сначала выбирается основной остов, а повторная родственная связь отображается как дополнительное ребро без дублирования карточки.

## 9. Обучаемое ранжирование — второй этап

Нейросеть не должна напрямую выдавать координаты. После появления надёжного генератора кандидатов можно обучить маленькую модель выбирать лучший допустимый вариант.

Обучающие данные:

```text
структура дерева
+ вариант алгоритма
+ исправленный пользователем вариант
+ какие карточки пользователь переместил
+ какой вариант был подтверждён
```

Модель возвращает дополнительную оценку кандидата. Жёсткие ограничения всегда проверяются обычным кодом и имеют приоритет над моделью.

До накопления достаточного числа примеров используется только детерминированная функция оценки. Родственные данные нельзя отправлять на сервер без отдельного явного согласия пользователя; предпочтителен полностью локальный ранжировщик.

## 10. Тестирование

### 10.1. Регрессионные примеры

- Все папки `TREEES/Проблема N` преобразовать в машиночитаемые тесты.
- В тесте хранить структуру, исходные координаты и ожидаемые свойства решения.
- Не требовать точного совпадения всех координат там, где существует несколько правильных вариантов.
- Проверять смысловые инварианты: стороны ветвей, центры, отступы, неподвижные якоря и отсутствие наложений.

### 10.2. Генеративные тесты

Автоматически создавать тысячи деревьев:

- глубина 1–8 поколений;
- 1–12 детей в семье;
- 0–4 партнёра;
- семьи разной ширины;
- неполные родители;
- боковые ветви с детьми;
- симметричные и почти симметричные ветви;
- циклические связи;
- несколько несвязанных компонентов.

Для каждого результата проверять:

- отсутствие пересечений карточек;
- корректность поколений;
- минимальные отступы;
- детерминированность;
- идемпотентность полного упорядочивания;
- ограниченную область изменений в локальном режиме;
- время выполнения;
- сохранение всех связей и людей.

### 10.3. Сравнение качества

Хранить метрики до и после изменения решателя:

- ширина и высота дерева;
- количество пересечений линий;
- суммарный сдвиг существующих карточек;
- сдвиг основной ветви;
- ошибка центрирования;
- ошибка симметрии;
- время выполнения.

Изменение нельзя принимать, если оно исправляет один пример, но статистически ухудшает общий набор.

Реализованные проверки этапа A:

- одинаковые контуры сравниваются по числу карточек и ширине на каждом уровне;
- нарушение поколений, выход с сетки и пересечение карточек отклоняют кандидата;
- операция сдвига полностью обратима;

### Этап B. Первый решатель

- [x] Реализовать генераторы сдвига семейного блока и боковой ветви.
- [x] Реализовать симметричное разделение двух ветвей.
- [x] Реализовать перестановку соседних братьев/семей.
- [x] Реализовать beam search с ограниченным числом кандидатов.
- [x] Подключить решатель сначала только в диагностическом режиме.
- [x] Сравнивать решение нового и текущего алгоритма в тестах.

Диагностическая версия уже умеет распознать одинаковые родительские ветви по связям,
создать зеркальный вариант, оценить его вместе с исходным расположением и выбрать вариант
с меньшим общим штрафом. При пересечении карточек она создаёт варианты сдвига всей боковой
семьи, а также умеет переставлять соседние братские семьи целиком. Она пока не заменяет
рабочий `TreeLayoutEngine` в приложении.

`LayoutSolverDiagnostics` запускает все готовые генераторы над текущим расположением,
возвращает обе оценки и предложенные операции, но принципиально не меняет `TreeState`.

### Этап C. Локальное добавление

- [x] Определять минимальную область влияния.
- [x] Запрещать движение основной и далёких ветвей.
- [x] Расширять область только при отсутствии решения.
- [ ] Заменить по одному текущие локальные обработчики общими операциями решателя (центрирование и интервалы уже подключены как проверяемый постпроцессор).

`LayoutImpactRegion` начинает с новых карточек и непосредственного якоря. Если решения нет,
область последовательно расширяется до семьи, братьев и сестёр, родителей, соседних по
контуру ветвей и предков. Все операции фильтруются через область; основная карточка и
люди за её пределами не могут быть сдвинуты. Расширение прекращается сразу после первого
допустимого решения.

Первым общим локальным обработчиком стал `FamilyCenterCandidateGenerator`: он предлагает
сдвинуть родительскую ветвь либо ветви детей и передаёт выбор функции оценки. Центр семьи
рассчитывается только по прямым детям и родителям, поэтому широкое нижнее поколение больше
не может увести родителей в сторону.

`SiblingSpacingCandidateGenerator` строит группы братьев и сестёр как по общим родителям,
так и по явным sibling-связям. Простые соседние ветви получают интервал в одну клетку;
если у любой ветви есть партнёр или потомки — пять клеток. Кандидат переносит всё поддерево
целиком и предлагает сдвиг левой стороны, правой стороны или симметричное разделение.

Проверенные операции подключены к рабочему `layoutAfterAddition` как безопасный локальный
постпроцессор только при включённой функции автоматической компоновки. Сначала сохраняется
результат прежнего алгоритма; предложение решателя применяется лишь при меньшем штрафе,
нуле жёстких нарушений, неподвижном root и неизменных карточках за пределами области.
При любом отказе остаётся прежнее расположение. Поиск ограничен 16 операциями на состояние.

`AncestrySideCandidateGenerator` определяет левую и правую ветви по положению партнёров,
а не по полу или ФИО. В сторону входят родители, все предки, боковые братья и сёстры
предков, их партнёры и потомки. Верхняя часть не может пересечь внутренний край карточки
своего потомка, а боковые семьи на том же или нижнем уровне остаются снаружи с интервалом
две клетки. Между левой и правой родительскими ветвями сохраняется пять клеток.

### Этап D. Полное упорядочивание

- [x] Использовать решатель на каждом шаге пошагового восстановления.
- [x] Добавить финальное уплотнение.
- [x] Обеспечить идемпотентность: повторное нажатие не меняет координаты.
- [ ] Добавить прогресс и отмену для очень больших деревьев.

Ручная команда полного упорядочивания принудительно запускает решатель после каждого
семейного шага независимо от переключателя автоматической компоновки. Для восстановления
используется отдельный быстрый профиль beam search: ширина 6, глубина 2. Он рассчитан на
уже допустимый результат локальной эвристики и ищет центрирование или раздвижение без
четырёхуровневой стоимости обычного локального режима.

Полное восстановление всегда начинает вычисления на каноническом поле 24 000 × 16 000,
а затем детерминированно расширяет его при необходимости. Старые координаты и размер,
полученный предыдущим запуском, больше не сдвигают центральную карточку. Настройка
автоматической компоновки пользователя при этом не меняется.

После завершения всех шагов выполняется отдельный глобальный проход уплотнения. Он
использует функцию оценки без штрафа за старые координаты, закрывает избыточные интервалы
между семейными ветвями и принимается только при реальном уменьшении ширины дерева.
Корневая карточка заблокирована; перестановка братьев исключена из набора операций;
дополнительно проверяются прежний горизонтальный порядок, все жёсткие ограничения и
отсутствие увеличения ширины. Поэтому этот проход не может ради компактности перемешать
семьи или испортить уже допустимую схему.

### Этап E. Сложные связи

- [x] Несколько партнёров и сводные дети.
- [ ] Неполные и дополнительные родители.
- [ ] Закреплённые карточки.
- [ ] Циклы и повторные связи между ветвями.
- [ ] Несвязанные компоненты.

Каждая пара или пара совместных родителей теперь представлена отдельным `PartnerUnit`,
даже если явная партнёрская связь отсутствует после развода. Один человек может входить
в несколько союзов, но его карточка остаётся единственной. Точные наборы родителей
образуют разные `ParentFamily`; дети с хотя бы одним общим родителем входят в общую
смысловую группу братьев и сестёр, не сливая при этом семейные блоки.

`MultiUnionFamilyCandidateGenerator` размещает потомков каждого союза отдельной ветвью,
центрирует второго родителя относительно только его детей и сохраняет общую карточку
неподвижной. Между детьми разных наборов родителей функция оценки и генератор интервалов
требуют пять клеток, даже если обе ветви состоят из одиночных детей. Локальный поиск для
добавления ребёнка в повторном браке завершается только после одновременного исправления
межсемейного интервала и центров затронутых союзов; допускается максимум два ограниченных
прохода по одной области влияния.

### Этап F. Обучаемые предпочтения

- [ ] Сохранять обезличенные локальные признаки ручных исправлений только с согласия пользователя.
- [ ] Подготовить формат обучающих пар.
- [ ] Обучить ранжировщик кандидатов.
- [ ] Запускать модель локально и оставлять обычную функцию оценки запасным вариантом.

## 12. Первый практический шаг

Начать с классов, не меняющих текущее поведение приложения:

```text
FamilyLayoutGraph
BranchContour
LayoutSnapshot
LayoutConstraints
LayoutWeights
LayoutScorer
LayoutOperation
```

Первый тестовый сценарий — симметричное дерево из файла `family-tree-2026-08-09 (3).ftree`. Новый код должен построить семейные блоки, вычислить одинаковые структурные сигнатуры ветвей и оценить асимметричный вариант хуже зеркального.

После этого добавить сценарии Проблемы 11:

- партнёр бокового родственника не должен заходить за противоположную родительскую ветвь;
- новый ребёнок не должен вставать поверх существующего;
- основная нижняя ветвь должна оставаться неподвижной.

## 13. Критерии готовности решателя

Решатель считается основной системой только когда:

- все существующие регрессионные тесты проходят;
- генеративные тесты проходят минимум на 10 000 деревьев;
- повторное полное упорядочивание идемпотентно;
- на деревьях до 500 карточек соблюдаются ограничения времени;
- локальное действие не двигает карточки за пределами рассчитанной области без доказанной необходимости;
- сложные браки и циклы не создают дубликатов и наложений;
- новый решатель по совокупной метрике не хуже текущего алгоритма;
- старые эвристики можно удалить без потери покрытых сценариев.

## 14. Правило дальнейшей разработки

Каждая новая найденная проблема оформляется в таком порядке:

1. Описать структуру связей и нарушенный инвариант.
2. Добавить воспроизводящий тест.
3. Определить, чего не хватает: ограничения, кандидата или веса оценки.
4. Исправить общий механизм.
5. Прогнать весь регрессионный и генеративный набор.

Запрещённый подход: добавлять проверку по ФИО, идентификатору файла, точному числу карточек или единственному набору координат конкретного примера.
